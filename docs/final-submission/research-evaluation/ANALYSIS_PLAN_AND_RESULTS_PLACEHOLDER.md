# Analysis plan and empty results sections

## Before collection

Register the approved package/version, task/scenario snapshot, recruitment/inclusion criteria, intended descriptive analysis and any pilot changes. Freeze a separate relevance-judgement set before tuning; never recycle exposed development cases as independent held-out evidence. Confirm that reviewers have not contributed labels used to tune the final artifact. The independent-judgement protocol is separate from usability satisfaction.

## Planned analysis

Count approached/consenting/completing/withdrawing participants only if ethically approved to record these counts. Report actual eligibility, languages/browser/device distribution and missing observations without adding unnecessary demographics. Show unassisted and assisted task completion n/N separately. Summarise valid task times with median/range or IQR and disclose exclusions, failures and time limits. Show errors/help requests and explanation rubric counts for each probe.

The eight custom questionnaire items use 1–5 plusN/A. Report item response distributions and denominators; no unvalidated overall SUS-like score. Analyse comments with a versioned coding table and retain critical/disconfirming observations. Do not claim saturation from convenience sampling. If a standard SUS instrument is separately approved and correctly sourced, keep it unmodified and document its conventional scoring independently; this package does not reproduce or administer one.

Compare ratings/ranking metrics only on fully judged candidate pools with nonzero ideal gain. Report nDCG at min(3,pool size), per-scenario/domain values, judge coverage and disagreement. Do not infer superiority from a change of order. Use development/validation/held-out separation for any later trained model; this prototype has no feedback training.
