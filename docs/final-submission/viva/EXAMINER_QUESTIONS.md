# Examiner questions and defensible answer notes

These are evidence-based draft answers for author review. They do not replace understanding the code or supply personal experiences. Exact question excerpts are now reproduced in RESEARCH_QUESTIONS.md; original-document comparison and genuine supervisor decisions are still required.

| Question | Defensible answer |
|---|---|
| What is the contribution beyond a course list? | The artifact combines structured constraints, explicit unknown evidence, conditional progression and bounded semantic exploration with an auditable technical evaluation. It is an application/design contribution, not a new encoder algorithm. |
| Where is the genuine AI? | A pretrained MiniLM sentence encoder performs local frozen ONNX inference over preference and programme descriptors. The rules and guided assistant are deterministic. |
| Did you train it? | No. The model was trained externally; I pinned and deployed it. TF–IDF fits catalogue statistics but does not learn learner preferences. |
| Does it learn from feedback? | No. No legitimate feedback training data exists here; automatic learning was deferred. A future study would require opt-in ratings and separated evaluation. |
| Why keep eligibility rule-based? | Formal source conditions should not be overridden by text similarity. Explicit rules provide traceable outcomes and unknown states. |
| Can an ineligible item outrank an eligible one? | Semantic ranking operates inside canonical academic groups. It cannot promote NOT_MET into MET. Unknown evidence remains a distinct group. |
| What does a score of0.8 mean? | A representation-specific cosine similarity, not80% admission, competence or success probability. Scores are not calibrated outcomes. |
| Is MET admission? | No. It means supplied evidence satisfies represented conditions. Provider/selection checks may remain unresolved; the prototype is guidance. |
| Why three states? | Absence of evidence is different from known failure. An incomplete profile or unknown provider decision should not become an automatic rejection or acceptance. |
| What concrete defect did evaluation find? | UGC general-entry/selection evidence was omitted for some state programmes. Source inspection led to provider-review rules and NOT_ASSESSED despite subject matches, then regression reruns. |
| Why did passing tests not catch that earlier? | Tests can reproduce the same incomplete assumptions as the code. Source adjudication is a different evaluation layer; independent review remains important. |
| What are the real final test results? | At07f4b97:205 backend,36 browser,5 live workflows,14 synthetic cases passed; integrity/fresh install passed. Command exit codes and logs are saved. |
| Do those counts prove educational accuracy? | No. They verify tested execution and integration. They do not establish comprehensive source correctness, recommendation relevance or satisfaction. |
| Does semantic ranking beat TF–IDF? | Not established. Nine synthetic functional comparisons exist, but independent relevance labels do not. nDCG was not computed. |
| How would you evaluate relevance? | Freeze a distinct held-out scenario set and candidate pools; obtain blinded independent graded judgements; compute within-group nDCG only where labels/ideal gain permit. |
| How do you avoid leakage? | Do not tune corpus/weights on held-out judgements. Future trained models split by participant/time; repeated sessions stay together. Current nine cases are development-functional examples. |
| Why not collaborative filtering? | There is no legitimate user-rating matrix. Synthetic feedback could test code but could not establish actual preference improvement. |
| Why11 programmes? | A realistic bounded demonstration within the curated project scope. Coverage is uneven and limits generalisation, especially Business. It is not national provision. |
| Are all sources independently verified? | Selected official requirements were checked and recorded; not all recognition/career-skill relationships were independently refreshed. Stored provenance and executed verification are distinct. |
| Are skill gaps competence assessments? | No. Explicit self-reports are compared with curated career skills. Unreported means unassessed, and relationship provenance is limited. |
| Is the chatbot generative AI? | No. It recognises bounded topics and returns structured read-only engine outputs, refusing unsupported free questions. |
| Does the app understand Sinhala/Tamil interests? | No such claim. It has draft translated interface controls; semantic input remains English-supported and educational source content may remain English. |
| Is speech entirely offline? | Not verified. Browser recognition may use vendor services. It is optional with consent/error states and text fallback; native language accuracy is pending. |
| Are you WCAG-compliant? | Not established. Nine axe-scanned states had zero detected violations and reflow passed; manual assistive-technology/zoom and other checks remain pending. |
| What usability results do you have? | None yet. Adult-only draft instruments exist, but signed ethics conditions must be checked before recruitment. No SUS or satisfaction score is invented. |
| Why DSR and iterative prototyping? | The research builds/evaluates an artifact addressing a bounded problem. Iterations refine it; the source-policy correction is a concrete evaluated change. Code delivery alone is not complete DSR evaluation. |
| What are the runtime costs? | Measured model load~0.29s, warm in-process p95~15ms and peak process RSS~302MiB on one Mac. This excludes download/full cold-machine startup and is not a load-test guarantee. |
| Why CSV and a modular backend? | They support a small inspectable/versioned snapshot and existing functionality. A database would not itself fix incorrect source rules; production scaling is future work. |
| What happens without a model? | Explicit unavailable metadata and RULE_BASED_FALLBACK retain academic assessment and within-group baseline order. Failed-load caches require restart after provisioning. |
| What data is collected? | The prototype accepts temporary reported qualifications/interests/skills without accounts. No feedback training store was added. Research templates request fictional tasks and minimal approved deidentified records. |
| What is the strongest limitation? | Technical success does not establish human usefulness. Independent relevance/source review, approved adult usability and fluent/manual validation remain needed. |
| Was AI used to produce the dissertation/code? | Yes, AI assistance was used in development and drafting. The author must accurately explain their work, verify sources and comply with the actual module's permitted-use/disclosure rules. No unaided-authorship declaration is fabricated. |
| Did the project meet every approved objective? | Not yet fully demonstrated: implementation is strong forIII–V, while literature/context, human evaluation and accessibility validation need review/completion.
