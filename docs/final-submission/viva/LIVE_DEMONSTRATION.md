## Demonstration sequence

1. **Profile compatibility:** use OL6 (MathematicsC, EnglishC, ScienceC, ICTS, SinhalaS, HistoryS). Find the recorded IIT foundation requirements. Explain that MET refers to represented conditions, not guaranteed admission. Show optional additional rows without requiring nine for every programme; OL9 is the saved complete-profile counterpart.
2. **Academic uncertainty:** use AL_IT (Combined MathematicsB, PhysicsC, ChemistryC) with an English software intention. Show an IT subject match, overall NOT_ASSESSED and the missing UGC evidence. Read the academic status independently from semantic similarity and open the source link. Do not claim the learner is admitted.
3. **Known unmet requirement:** use AL_Engineering_gap and engineering intention. Show failed Physics and the NOT_MET explanation. A high relevance score, if present, cannot repair it. Compare a missing-evidence case rather than calling both rejected.
4. **Vocational progression:** choose the catalogue NVQ6 Mechatronics qualification from NVQ6, inspect UoVT's conditional route and remaining provider checks. Explain that reported awards, equivalence and exemptions are not authenticated.
5. **Skills and guided support:** select a supported career, mark a listed skill reported and leave another unreported. Show the self-report caveat. Ask the guided eligibility/skills topic; demonstrate an unsupported question refusal without inventing an answer. Show historical scholarship status and official link without promising funding.
6. **Language and text fallback:** switch en→si→ta; show preserved inputs/results and untranslated official text labels. State translations are drafts and semantic preferences remain English-supported. Show voice availability/consent controls and the working text input. Do not imply a headless/mocked event was native speech.

## Optional model-failure demonstration

Use the saved runtime-network.json and explain the executed missing-model subprocess. If a live fallback is required, start a separate API process with WISELANKA_MODEL_DIR pointing to an absent directory and a separate port, then use a separate browser context/API base. Do not alter the valid model directory or stop someone else's server. The expected method is RULE_BASED_FALLBACK with LOCAL_MODEL_UNAVAILABLE and no semantic probability. Restart after provisioning if a process cached a failed load.

## Failure recovery

- API failure: show error state, verify base/server; if unresolved, explicitly switch to saved WP5 screenshots/logs. Do not call them live output.
- Model unavailable: explain explicit fallback and continue formal assessment; do not conceal missing AI.
- Official source inaccessible: use recorded URL/hash/page reference and label it previously checked; do not claim current access succeeded.
- Native speech unavailable/refused: type the question; this is an intended supported route. Do not pressure microphone use.
- Language rendering/font issue: record it, use English fallback and disclose the limitation.
